## 1. 听歌历史与热力图

- **借鉴点**：ECHO 将每次播放记录与每日统计分开，提供历史筛选、已听时长、热力图和常听排行。
- **当前基础**：NekoTune 已有 `play_count`、`last_played_at`、最近播放排序和首页入口，但这些字段不能还原逐次播放记录或实际收听时长。
- **首期范围**：
  - 新增播放会话记录：歌曲身份、开始时间、实际收听时长、结束原因、是否完整播放。
  - 历史页支持今天／近 7 天／近 30 天、歌曲搜索和完整播放筛选。
  - 首页增加近一个月听歌热力图、本周收听时长、常听歌曲；首次使用展示空状态。
- **实现重点**：由后端基于确认的播放状态计时，暂停、卡顿、seek 跳过的时间不算收听时长；多前端不能重复记账。UTC 存储，按用户本地日期展示，支持清空历史。
- **落点**：`backend/application/playback/`、`backend/storage/`、首页与新增历史页；新增记录查询采用分页，统计在数据库聚合。
- **验收**：暂停续播不重复创建会话；重复入队可区分不同播放；跨午夜、手动切歌、自然结束和重启结果正确。旧数据仅保留已有次数，不伪造历史时长。

## 2. ReplayGain／响度均衡

- **借鉴点**：ECHO 提供单曲／专辑模式，并把响度处理、余量和输出保护放在同一条音频处理链中。
- **当前基础**：已有 FFmpeg 解码、连续 PCM 输出、10 段 EQ、自动余量和限幅；可在现有处理链增加响度增益，不再以 Qt 主音量缩放作为主方案。
- **首期范围**：
  - 默认关闭，支持单曲／专辑模式和预增益。
  - 优先读取已有 ReplayGain 标签；缺少数据时允许用户启动后台分析。
  - 显示当前歌曲使用的增益及数据来源，缺少数据时明确回到不补偿状态。
- **实现重点**：分析可取消、限制并发，播放期间降载；结果只写数据库或缓存，不自动改写原音频。增益与 EQ／限幅统一计算，切歌平滑切换；Crossfade 两路分别应用各自增益。Qt 后端不具备同等能力时明确显示不可用／旁路。
- **落点**：`backend/infrastructure/library/audio_duration.*`、`backend/infrastructure/playback/pcm_dsp.*`、`backend/application/playback/audio_settings_service.*`。
- **验收**：验证标签优先级、专辑内相对音量、缺少标签、静音样本、正增益与削波保护、Crossfade 和后端回退。对有足够余量的样本验证响度收敛；分析前后原文件哈希保持不变。
- **关联**：[现有待办](docs/todo.md)第 1.4 项。实施前更新该项仍按旧 Qt 路径描述的部分。

## 3. 自动备份与可回滚恢复

- **借鉴点**：ECHO 将手动备份、周期备份、数据迁移和恢复入口集中管理。
- **当前基础**：曲库、歌单、队列及歌词资料依赖本地持久化，已有待办 6.1 规划一致性备份。
- **首期范围**：
  - 设置页提供立即备份、备份目录、最近成功时间和恢复入口。
  - 数据库迁移前自动快照；可选周期备份和保留份数，明确展示失败状态。
  - 备份包含一致性数据库、必要设置和清单；默认不打包音频文件、可再生成缓存或密钥。
- **实现重点**：使用 SQLite backup API 或 `VACUUM INTO`，不能直接复制仍在写入的数据库文件。恢复前校验版本与校验和，先备份当前数据，再按受控停机／重启流程替换；跨机器路径失效应保留资料并提示重新定位。
- **落点**：独立备份服务、存储层与设置页；避免把归档和恢复逻辑写进播放引擎。
- **验收**：播放和写库期间生成的备份可打开；损坏包、较新 schema 和磁盘空间不足不会破坏现有数据；恢复失败可回滚；备份中不含 API Key、Cookie 或访问令牌。
- **关联**：现有待办 6.1，共用一套实现。

## 4. 歌词场景预设

- **借鉴点**：ECHO 把歌词布局、字体、辅助行、封面和背景参数组合成可切换的视觉体验。
- **当前基础**：已有主歌词、迷你歌词、桌面歌词与共用时间轴；工作区还在增加音乐壁纸和可切换布局，应基于这些组件扩展。
- **首期范围**：
  - 三个预设：阅读优先、封面与歌词并排、全屏歌词。
  - 保存字体、字号、行距、当前行／上下文透明度、封面布局、背景模糊和颜色。
  - 支持保存当前配置、重命名、恢复默认，以及带版本号的 JSON 导入／导出。
- **实现重点**：复用 `LyricsClock`、`LyricLine`、`CompactLyrics`；切换仅改变视觉布局，不重载音乐、不重复请求歌词。预设只承载声明式配置，外部字体／图片缺失时回退；主窗口、壁纸、桌面歌词只应用各自支持的字段。
- **落点**：`frontend/qt-qml/qml/components/`、当前壁纸布局和外观设置控制器。
- **验收**：连续切换预设不跳歌词、不改变播放位置；隐藏布局释放动画与计时器；损坏或未知版本预设可拒绝并保留当前配置；中英文和缩放正常。
- **后续边界**：真实音乐响应背景等到 PCM 分析／频谱接口完成后再做，不用装饰动画冒充音频分析结果。

## 5. 耳机校正预设

- **借鉴点**：ECHO 的 OPRA 目录允许按品牌、型号和测量来源选择校正曲线，比只提供“低音增强”之类通用预设更具体。
- **当前基础**：已有 10 段图示 EQ、前级、预设和限幅，但不能精确执行任意参数 EQ 曲线。
- **首期范围**：
  - 先做校正配置的导入、收藏、来源显示、A/B 旁路和恢复原 EQ。
  - 对当前 10 段 EQ 可表达的配置直接应用；无法表达的参数曲线明确提示不支持，不静默近似。
  - 后续再扩展参数 EQ，并接入按品牌／型号检索的 OPRA 目录与离线缓存。
- **实现重点**：记录曲线版本、测量来源、目标曲线和建议前级；校正配置与用户手工 EQ 的覆盖／叠加关系必须明确。切换设备不自动套用未经用户选择的耳机配置。
- **落点**：现有音频设置服务与 PCM DSP；目录检索和缓存独立于实时音频路径。
- **验收**：配置切换平滑、建议前级得到保留、旁路恢复正确；用频率响应样本验证实现，不以主观“更好听”作为唯一标准。
- **排序**：响度均衡和当前 EQ 平台验收完成后再推进；OPRA 数据接入时核对来源和使用条款。

## 6. 手机扫码遥控 MVP

- **借鉴点**：ECHO Link Basic 用扫码配对和范围明确的播放 API 实现轻量手机遥控。
- **当前基础**：已有本地 Socket 请求／响应／事件协议，桌面与独立前端共用后端；现有待办 8.1 规划完整 Web 网关。
- **首期范围**：
  - 默认关闭；开启局域网遥控后，显示短时有效二维码与可撤销的已配对设备。
  - 手机浏览器显示当前歌曲、封面、进度和音量，支持播放／暂停、上下首、seek、音量。
  - 不包含曲库编辑、扩展管理、音频串流、多人一起听歌或公网中继。
- **实现重点**：独立网关只映射明确允许的命令，不能把整个 Socket API 原样暴露。状态仍以后端确认为准；短期配对凭证换取设备令牌，支持撤销、限流和 Origin 校验，不在普通 URL、日志或备份里泄露长期令牌。
- **落点**：可选网关模块＋小型静态 Web 页面，复用现有应用服务，不另建播放状态机。
- **验收**：未配对请求被拒绝；二维码过期／撤销后立即失效；手机断线重连不重复执行操作；多个前端同步一致；无法调用文件删除、扩展安装和密钥设置接口。
- **关联**：现有待办 8.1。只提前实现基础遥控，完整远程浏览与 Web 前端保留原 P3 范围。

## 建议实施顺序

1. 自动备份：先保护现有资料，也为后续数据迁移提供回退。
2. 响度均衡：利用已有 PCM／EQ 能力，直接改善混合歌单体验。
3. 听歌历史：补齐记录，再增加热力图和统计展示。
4. 歌词场景预设：等当前壁纸与共用歌词组件稳定后接入。
5. 手机基础遥控：围绕已有 IPC 做有限功能网关。
6. 耳机校正：先验证配置模型和 DSP 能力，再接在线目录。
