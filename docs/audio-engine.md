# 统一音频引擎

默认后端为 FFmpeg，Qt Multimedia 作为可选兼容后端。设置中的后端偏好重启生效；发生尚未输出音频的格式／解码初始化错误时，当前播放实例最多回退 Qt 一次，下一次加载新源重新尝试所选后端。网络、设备、存储和预加载失败不触发该回退。

FFmpeg 引擎当前仅支持 1.0×；已有倍速设置不会被启动过程覆盖。需要保留音高的倍速可选择 Qt 并重启。Gapless 自动启用，Crossfade 默认关闭、可设置 0–12 秒，只用于自然换曲。严格同专辑顺序和单曲循环使用 Gapless；手动切歌、seek 和停止取消旧过渡。暂停保留两路位置与渐变进度。

EQ 为 31 Hz–16 kHz 的 10 段一倍频程滤镜，各段与前级范围均为 ±12 dB，支持平直／低音增强／人声／明亮预设以及保留的自定义曲线。默认关闭，自动余量默认开启。参数以约 20 ms 平滑更新，关闭 EQ 不清除滤镜状态或重建输出。低于当前输出奈奎斯特频率的频段才可启用。

## 实现边界

- 两路解码工作线程分别产生经过 priming/padding 裁剪的原生采样率立体声浮点数据；MP4/AAC 还使用编辑列表结束时间裁剪最后一帧。seek 从目标前最多一秒预滚，按采样时间戳精确裁剪。
- 输出线程负责连续重采样、过渡、DSP 和 `QAudioSink`。同采样率的连续源保留重采样历史与分数相位；异采样率分别排空。每路原生缓冲 15 MiB、规范化缓冲 12 MiB，余量用于转换与输出；高采样率或准备不足时缩短 Crossfade，下一首未就绪则普通换曲。
- 解码和写入设备缓冲都不更新队列身份。可推进的 `PcmOutputClock` 以已处理帧数发布边界，应用线程保存选择后再确认随机历史、更新歌词／MPRIS 和播放次数。边界保存失败停播，保留旧选择和历史。
- 当前、预加载和混音尾音的扩展代理 URL 分开持有；过期解析立即释放，旧 URL 在尾音退出后释放。停止、seek、设备丢失和关闭均清理预加载；设备恢复不自动播放。
- 设备时钟代表 Qt 报告的处理进度，不能用于声称物理扬声器零延迟。无干预且下一首已准备好的采样衔接，与设备拔插／主动操作后的恢复分开验收。

## 自动化验证

```sh
cmake --build build --parallel
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software \
  ctest --test-dir build --output-on-failure
pnpm --dir extensions check
uv run --no-project --python 3.12 -m unittest discover -s scripts/ci/tests
```

`nekotune_audio_pipeline_test` 无需声卡或网络，覆盖逐样本的连续重采样、连续短曲、异采样率／单声道、生成的 FLAC/MP3/AAC/Opus 的延迟／尾部裁剪和 seek、混音长度、EQ 频响／旁路／限幅、可推进输出时钟、一次性回退、队列保存失败、随机候选失效、重复歌曲和资源释放。

`nekotune_audio_pipeline_network_test` 使用临时本地 HTTP 服务验证 Range/seek、过期音源错误分类和阻塞读取取消。IPC 测试验证设置、多客户端确认值、重启持久化和非法参数。QML 测试验证后端选择、EQ 调节、能力禁用和窄布局；所有音频测试样本均为生成信号，不含外部录音。

## 平台验收

自动化构建与测试不替代以下真机检查，尚未据此宣称全部完成：

- Linux PipeWire/PulseAudio 与 Windows 实际声卡：选择设备／端口、拔插、默认输出改变、无设备启动和恢复后保持暂停。
- 捕获实际输出验证长专辑连续播放、44.1/48/96/192 kHz 切换、Crossfade 峰值与 EQ 快速调节听感，观察欠载及资源占用。
- 从发行包启动，检查新增 FFmpeg 库和 Qt 音频插件的依赖闭包；Windows 同时验证中文文件路径及后端重启偏好。
- 长时间播放与反复 seek／暂停／停止／扩展重载，检查线程、内存、代理 URL 和设备资源能否正常回收。
