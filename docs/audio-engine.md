# 统一音频引擎

默认后端为 FFmpeg，Qt Multimedia 作为可选兼容后端。设置中的后端偏好重启生效；发生尚未输出音频的格式／解码初始化错误时，当前播放实例最多回退 Qt 一次，下一次加载新源重新尝试所选后端。网络、设备、存储和预加载失败不触发该回退。

FFmpeg 引擎当前仅支持 1.0×；已有倍速设置不会被启动过程覆盖。需要保留音高的倍速可选择 Qt 并重启。Gapless 自动启用，Crossfade 默认关闭、可设置 0–12 秒，只用于自然换曲。严格同专辑顺序和单曲循环使用 Gapless；手动切歌、seek 和停止取消旧过渡。暂停保留两路位置与渐变进度。

EQ 为 31 Hz–16 kHz 的 10 段一倍频程滤镜，各段与前级范围均为 ±12 dB，支持平直／低音增强／人声／明亮预设以及保留的自定义曲线。默认关闭，自动余量默认开启。参数以约 20 ms 平滑更新，关闭 EQ 不清除滤镜状态或重建输出。低于当前输出奈奎斯特频率的频段才可启用。

ReplayGain 默认关闭，可选择单曲／专辑模式及 ±12 dB 预增益。当前歌曲的对应模式标签优先于分析缓存；流标签优先于容器标签，非法、非有限或超出 ±60 dB 的标签不采用。缺少对应模式数据时应用 0 dB，预增益也不生效；专辑模式不回退单曲增益。界面显示当前 ReplayGain 增益、标签／分析来源和峰值余量限制，Qt 后端显示不可用／旁路并保留配置。

处理顺序为「逐路重采样 → 逐路 ReplayGain → Crossfade 混音 → EQ 前级及自动余量 → 10 段 EQ → 统一限幅 → 输出」。已知峰值限制 ReplayGain 增益，专辑模式使用共同专辑峰值；未知峰值、EQ 正增益和混音峰值由最终限幅保护。参数与 Gapless 边界使用约 20 ms 的逐样本增益过渡，Crossfade 两路分别使用自己的增益。显示的增益不包含 EQ 衰减和限幅器的瞬时衰减。

设置页可手动分析本地曲库的缺失数据。单任务、单文件解码，分析线程低优先级、解码器单线程及 256 KiB 缓冲；播放／加载期间每 4096 帧额外分段等待约 40 ms，可随时取消。使用 [FFmpeg ebur128](https://ffmpeg.org/ffmpeg-filters.html#ebur128) 测量送往立体声输出的 48 kHz PCM，目标 −18 LUFS，并测量 true peak。数字静音、低于绝对门限和不足 400 ms 的单曲不生成单曲增益。限幅或峰值余量限制生效时不保证达到目标响度。

专辑按曲库中忽略大小写的「专辑名＋专辑歌手（为空时回退歌曲歌手）」归组，按碟号／音轨号／歌曲 ID 顺序连续测量，并给成员保存相同的专辑增益和峰值。仅选部分歌曲时仍分析其完整已入库专辑；没有专辑名或存在离线成员时只生成单曲结果。未入库的专辑成员无法推断，修改专辑归组或补充成员后可重新启动分析。

结果原子写入应用配置目录的 `loudness/*.json` 缓存，不修改原文件或内嵌标签。缓存以规范路径、文件大小、修改时间和元数据变更时间校验；专辑缓存还校验所有成员。成员变更使专辑增益失效，未变更文件的单曲结果仍可用。取消不保存未完成的测量，已完成结果保留，重启不恢复分析任务。缓存丢失时回到标签或不补偿，运行期间完成的分析会平滑应用到已加载音源。

## 实现边界

音乐壁纸前端消费既有播放、歌词状态及可选扩展频段事件，不持有原始 PCM、不增加解码器或输出。SDK 3 提供默认 FFmpeg 后端的只读 PCM 观察接口，由独立原生扩展执行 FFT 和分发频段；Qt 兼容后端明确不支持 PCM。内置装饰动画仍只跟随播放状态，设置页说明频谱由扩展提供。

- 两路解码工作线程分别产生经过 priming/padding 裁剪的原生采样率立体声浮点数据；MP4/AAC 还使用编辑列表结束时间裁剪最后一帧。seek 从目标前最多一秒预滚，按采样时间戳精确裁剪。
- 输出线程负责连续重采样、过渡、DSP 和 `QAudioSink`。同采样率的连续源保留重采样历史与分数相位；异采样率分别排空。每路原生缓冲 15 MiB、规范化缓冲 12 MiB，余量用于转换与输出；高采样率或准备不足时缩短 Crossfade，下一首未就绪则普通换曲。
- 解码和写入设备缓冲都不更新队列身份。可推进的 `PcmOutputClock` 以已处理帧数发布边界，应用线程保存选择后再确认随机历史、更新歌词／MPRIS 和播放次数。边界保存失败停播，保留旧选择和历史。
- 当前、预加载和混音尾音的扩展代理 URL 分开持有；过期解析立即释放，旧 URL 在尾音退出后释放。停止、seek、设备丢失和关闭均清理预加载；设备恢复不自动播放。
- 设备时钟代表 Qt 报告的处理进度，不能用于声称物理扬声器零延迟。无干预且下一首已准备好的采样衔接，与设备拔插／主动操作后的恢复分开验收。

## 平台验收

自动化构建与测试不替代以下真机检查，尚未据此宣称全部完成：

- Linux PipeWire/PulseAudio 与 Windows 实际声卡：选择设备／端口、拔插、默认输出改变、无设备启动和恢复后保持暂停。
- 捕获实际输出验证长专辑连续播放、44.1/48/96/192 kHz 切换、Crossfade 峰值与 EQ 快速调节听感，观察欠载及资源占用。
- 从发行包启动，检查新增 FFmpeg 库和 Qt 音频插件的依赖闭包；Windows 同时验证中文文件路径及后端重启偏好。
- 长时间播放与反复 seek／暂停／停止／扩展重载，检查线程、内存、代理 URL 和设备资源能否正常回收。

## 只读 PCM 分析

SDK 3 的 `context.pcm().capabilities()` / `subscribe()` 由后端线程的 `PcmService` 支持，`PluginManager` 依赖领域端口 `IPcmSource`。
默认 FFmpeg 后端在混音／DSP 后复制立体声数据到固定容量历史区，按 `QAudioSink` 消费帧时钟
投递到 SPSC 队列；分析副本应用当前播放器音量，不修改播放样本。无订阅不复制。
队列最多 64×512 帧，历史容量 262144 帧；生产者不分配内存、不等待消费者。
seek、换源、设备重建清空历史并递增代次，后端回退会停止可用能力。
分析订阅及 FFT 生命周期属于扩展，原始 PCM 不经过前端 IPC。
