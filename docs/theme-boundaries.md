# 主题职责与接口边界

本文规定主题、界面扩展、功能扩展与宿主之间的职责划分，回答三个问题：**一件事该由谁做、主题能用哪些接口、主题被重建时什么必须保持不变**。

- 主题格式、导入与操作见[主题制作](themes.md)，扩展清单与贡献见[扩展开发](extensions.md)，IPC 协议见 [API 文档](API.md)。
- 职责归属冲突时以本文为准；字段、取值与具体行为以格式文档和实现为准。
- 本文不新增清单类型、字段、IPC 方法或版本号。

## 0. 阅读约定

### 0.1 一句话原则

> **主题决定“看起来怎样、怎么操作”，宿主和功能扩展决定“发生了什么、结果是否成立”。**

主题只能呈现宿主**已有**的能力，并把用户的**明确操作**转交给宿主；它不拥有业务数据、业务规则和运行生命周期。

### 0.2 规范用语

| 用语 | 含义 |
| --- | --- |
| **必须 / 禁止** | 违反即为缺陷，评审不得通过 |
| **应当 / 不应** | 默认要求；例外须在评审中说明理由 |
| **可以** | 允许，不作要求 |

### 0.3 条目状态标记

本文每条规则都属于以下三类之一。三类不能混用：“约定”不等于运行时会拦截，“目标”不能当作已发布功能宣传。

| 标记 | 含义 | 是否有运行时保证 |
| --- | --- | --- |
| 【现状】 | 当前实现的真实行为，可在代码中验证 | 有，以实现为准 |
| 【约定】 | 对主题作者、模板和评审的要求 | **没有**，依赖评审与自律 |
| 【目标】 | 规划中的迁移，需单独设计、实现、测试后发布 | 尚不存在 |

## 1. 角色与包类型

### 1.1 五种角色

| 角色 | 负责什么 | 对应机制 | 能否带后台代码 |
| --- | --- | --- | --- |
| **外观主题** | 颜色、字体、间距、尺寸、圆角、动效参数、静态背景 | `tokens`、`variants`、`background` | 否 |
| **界面主题** | 已有功能的布局、视觉组件、页面呈现与交互；可覆盖整个窗口或局部区域 | `ui.shell`、`ui.pages`、`ui.bottomPlayer`、`ui.background`、`ui.wallpaper` | 否 |
| **界面扩展** | **新增**可被发现的页面、设置页、工具栏，或提供独立插槽替换 | 普通扩展的 `pages`、`settings`、`toolbars`、`slots` 等贡献 | 可以没有 |
| **功能扩展** | **新增**业务能力：音源、歌词源、命令、随机算法、后台服务等 | 普通扩展及原生 SDK 注册接口 | 是 |
| **宿主** | 业务控制器、领域规则、持久化、系统集成、界面加载与恢复 | 前端 C++、后端、宿主 QML 入口 | — |

### 1.2 包类型与角色的关系

【现状】

- 外观主题和界面主题是**两种职责**，不是两个 `type` 值；同一个主题贡献可以同时提供两者。
- 主题专用包使用 `type: "theme"`，**只能**贡献 `themes`，不能包含扩展库、原生模块、后台入口或扩展依赖，宿主在安装和重载时会校验这些限制。
- 普通扩展可以附带主题，但仍按普通扩展管理（启停、更新、后台服务），不改称主题包。

### 1.3 如何判断一项需求属于谁

**按职责判断，不看实现语言，也不看它有没有界面。** 依次问下面的问题，第一个回答“是”的就是归属：

1. 是否需要新的数据来源、网络请求、凭据、文件读写、数据库访问或定时后台任务？→ **功能扩展**（或先补宿主接口）
2. 是否改变业务规则或结果，例如去重、排序写回、播放顺序、校验、保存语义？→ **宿主 / 功能扩展**
3. 是否要向其他界面注册一个可被发现的页面、设置项、菜单或命令？→ **界面扩展**
4. 是否只改变已有功能的样子、位置或操作方式？→ **界面主题**
5. 是否只改变变量值或静态背景？→ **外观主题**

例如：同样是 QML，在主题里直接联网取歌词、发起下载、开定时器切歌，都属于**功能**；而用宿主已有的搜索和下载接口画出搜索框和下载按钮，属于**界面**。主题内部的说明页、装饰组件不算注册新页面。

### 1.4 边界案例

| 场景 | 归属 | 说明 |
| --- | --- | --- |
| 把播放栏改成圆形唱片样式 | 界面主题 ✅ | 只改呈现 |
| 在主题首页放“随机播放全部”按钮，点击后调用宿主播放接口 | 界面主题 ✅ | 用户明确操作，复用已有能力 |
| 主题加载完成后自动开始播放 | ❌ 禁止 | 初始化不得触发业务操作（§3.2） |
| 主题用 `XMLHttpRequest` 访问歌词网站 | 功能扩展 | 网络提供方不进入主题 |
| 主题里提供歌词搜索框，搜索由宿主歌词控制器执行 | 界面主题 ✅ | 主题只负责输入和展示 |
| 列表按“最近添加”排序显示 | 界面主题 ✅ | 前提是不写回歌单或队列顺序 |
| 拖拽排序后把新顺序提交给宿主 | 界面主题 ✅ | 由宿主接口提交，并等待结果 |
| 主题自己维护一份“当前队列”数组 | ❌ 禁止 | 第二份权威状态（§3.1） |
| 新增“智能电台”算法 | 功能扩展 | 新业务能力 |
| 在侧栏新增一个“统计”页面，供其他界面发现 | 界面扩展 | 新的可发现入口 |
| 自定义删除确认框的样式 | 界面主题 ✅ | 不得隐藏删除范围或改写确认结果 |
| 记住抽屉宽度、折叠状态 | 主题局部状态 | 允许重建后丢失；不得写入用户数据目录 |
| 设计一套唱片样式的桌面壁纸布局 | 界面（主题或界面扩展）✅ | 只用宿主提供的壁纸上下文呈现 |
| 选择主题时自动开启桌面壁纸 | ❌ 禁止 | 辅助窗口开关归用户和宿主（§6.2） |
| 壁纸显示真实音频频谱 | 功能扩展 + 宿主接口 | 新数据来源；当前没有频谱接口 |
| 界面布局里写死 `#FF0000` 作为强调色 | ❌ 不应 | 会导致无法与其他外观组合（§5.3.4） |

## 2. 职责分配

### 2.1 按功能域划分

| 功能域 | 主题可以 | 主题禁止 | 宿主 / 功能扩展必须负责 |
| --- | --- | --- | --- |
| 曲库、歌单、队列 | 布局、列表展示、选中反馈、发起明确的用户操作 | 自建权威列表；排序或筛选时暗中写回；混淆歌曲 ID 和队列项 ID | 数据身份、去重、导入目标、队列提交、失败回滚、持久化 |
| 播放 | 播放栏、进度展示、用户触发的播放、暂停、跳转请求 | 自动播放；自行计算下一首；用定时器驱动切歌 | 播放状态、队列顺序、随机算法、输出设备、解码、音频生命周期 |
| 歌词、封面 | 排版、动画、滚动、按已公开数据同步展示 | 自行请求网络、解析歌词文件、缓存封面 | 提供方选择、网络请求、解析匹配、缓存、封面来源 |
| 编辑与删除 | 编辑器样式、输入草稿、确认界面、进度和错误展示 | 隐藏删除范围；改写确认结果；视图销毁时自动提交草稿 | 字段语义、业务校验、保存、文件操作、结果确认 |
| 导航与扩展入口 | 导航位置、分组、展示方式、当前视图 | 隐藏已注册扩展页面的唯一入口（精简界面另见 §5.3） | 页面与能力注册、稳定 ID、可用性、扩展安装与启停 |
| 系统窗口 | 请求宿主已公开的显示、隐藏或窗口模式操作 | 创建或销毁主窗口；接管托盘、系统媒体集成或退出流程 | 主窗口生命周期、托盘、系统媒体集成、壁纸原生窗口、应用退出 |
| 桌面壁纸 | 壁纸布局、动画、歌词排版；遵守歌词开关、刷新频率、装饰强度和减少动态效果 | 开关壁纸；创建桌面窗口；自行获取播放或歌词数据 | 原生桌面窗口、每屏实例、启用与样式偏好、壁纸上下文数据（`api.wallpaper`） |
| 外观与设置 | 读取主题变量、呈现设置项、声明支持的界面能力 | 改写用户的主题或明暗选择；伪造授权 | 用户选择、明暗模式、管理操作、授权、持久设置、恢复入口 |

### 2.2 通用开发约定

【约定】以下规则适用于所有主题 QML 和 JavaScript。

1. **请求与结果分离**：主题通过宿主公开的控制器、模型和接口发起请求，**必须**等待成功或失败结果；不能把一次点击或乐观展示当成业务已经完成。乐观展示必须能在失败后回滚。
2. **只由明确动作触发业务**：初始化、重载、配色变化、窗口尺寸变化和视图销毁**禁止**触发播放、导入、下载、删除、后台服务启停等业务操作。只有用户的明确动作或宿主已有的业务流程可以触发。
3. **不引入业务基础设施**：网络提供方、凭据、数据库访问、用户数据文件读写、下载与重试、后台定时任务**禁止**放进主题。缺少能力时，先补宿主接口或功能扩展，再由主题使用。
4. **保持既有语义**：界面排序、筛选和选中**不得**改变持久化的队列、歌单顺序或播放意图。歌曲 ID 与队列项 ID、“导入曲库”与“加入队列”等既有区分必须保持。
5. **优先复用宿主流程**：元数据、标签、AI 建议、删除确认等流程**应当**复用宿主组件和控制器。自定义组件必须遵循同样的语义：字段缺失、显式清空、草稿保存、取消和错误。

## 3. 状态与生命周期

### 3.1 状态归属

“需不需要写入磁盘”和“需不需要跨主题切换保留”是两个独立的问题：宿主拥有的会话状态不一定要持久化。

| 状态 | 拥有者 | 主题重建后 | 主题禁止 |
| --- | --- | --- | --- |
| 歌曲、队列、播放位置、账号、业务设置 | 宿主控制器与后端 | 必须保持 | 重置；复制成第二份权威状态 |
| 当前页面 ID、当前歌单 ID、搜索与筛选条件 | 宿主或功能控制器（会话状态） | 【目标】恢复仍存在、且新界面支持的入口 | 把它们作为唯一副本保存在主题内 |
| 悬停、焦点、过渡动画、抽屉展开、局部滚动位置 | 主题 | 允许丢失 | 持久化到用户数据目录 |
| 未保存的编辑草稿、待确认操作 | 对应编辑流程 | 【目标】切换前提示保存或放弃 | 视图销毁时自动提交 |
| 未完成的业务请求 | 宿主或功能扩展 | 由拥有者完成、取消并报告 | 已销毁的视图接收迟到回调并应用结果 |

【现状】宿主始终持有播放和队列控制器；`Main.qml` 持有内置 Shell 的部分导航状态；自定义 Shell 可能把导航和草稿留在自己的 QML 里。跨 Shell 的状态恢复和切换前的草稿协调**尚未提供**，因此不能宣称任意主题重载都会保留这些状态。

### 3.2 重建时机

【现状】每个主题 QML 入口由一个 `ExtensionView` 承载，并使用**独立的 `QQmlEngine`**。入口描述（descriptor）一旦变化，就会销毁旧根对象和旧引擎，再新建引擎加载新入口。

| 事件 | 是否重建主题 QML | 主题应怎样应对 |
| --- | --- | --- |
| 明暗切换、系统配色变化 | **否**，同一入口只更新 `api.theme` 的值 | 绑定变量，不缓存颜色值 |
| 切换到另一个主题 | 是 | 不依赖销毁回调完成业务 |
| 更新主题包、重新加载、开发目录变动 | 是（generation 变化） | 同上；局部状态允许丢失 |
| 启停所在扩展、进入安全模式 | 是，回退到下一层插槽 | 同上 |
| 窗口尺寸变化 | 否 | 响应式布局 |

【现状】视图销毁时，`ExtensionApi` 会以 `Extension view unloaded` 拒绝所有尚未完成的 `call()` Promise。主题必须把这种拒绝当作“视图已卸载”处理，不能当作业务失败提示给用户，也不能重试。

【约定】主题 QML 可以被随时销毁重建，**禁止**拥有播放器、业务服务或主窗口的运行生命周期，也不能依赖 `Component.onDestruction` 完成任何业务操作。

## 4. 主题可用的接口

### 4.1 稳定性分级

| 级别 | 含义 | 使用要求 |
| --- | --- | --- |
| **公开** | 文档已承诺，变更会走兼容流程 | 可以直接依赖 |
| **有限公开** | 可以使用，但只承诺文档列出的部分 | 只用列出的成员；其他成员视为内部 |
| **内部** | 能访问到，但随时可能变化 | 不应依赖；如需使用须写明适配的宿主版本并提供回退 |

### 4.2 `ExtensionApi`（`import NekoTune 1.0`）

| 成员 | 内容 | 级别 | 边界说明 |
| --- | --- | --- | --- |
| `theme` | 已合成的外观变量（`Theme` 单例），包括 `isDark`、`reducedMotion` | 公开 | 必须用它取色和尺寸，不另建一套脱离用户选择的全局变量 |
| `wallpaper` | 壁纸入口的只读上下文；在其他视图中为 `null` | 公开 | 只读；原生窗口与播放状态归宿主 |
| `t(value)` | 按当前语言解析 `{zh, en}` 标签 | 公开 | — |
| `app` | 宿主控制器集合：`playback`、`audioOutput`、`queue`、`playlists`、`library`、`storage`、`history`、`tags`、`lyrics`、`settings`、`ai`、`extensions`、`theme` | 有限公开 | 按控制器已公开的方法和结果语义使用；能调用不代表适合主题调用，仍受 §2 约束 |
| `call(method, params)` | 把 IPC 请求转发给后端，返回 Promise | 有限公开 | 【现状】**没有方法白名单**，任何 IPC 方法都能被转发。【约定】主题只用于呈现所需的查询，或由用户明确操作触发的请求；优先使用 `app` 上的控制器 |
| `invoke(service, params)` | 调用本扩展自己注册的后台服务 | 有限公开 | 主题专用包没有后台，不应使用；仅适用于附带主题的普通扩展 |
| `event` 信号 | 本扩展后台推送的事件 | 有限公开 | 同上 |
| `window` | 宿主主窗口的根 QML 对象 | **内部** | 【现状】暴露的属性很多；其属性、页面树和 JavaScript 函数**都不是**主题接口 |

【现状】`ExtensionView` 还向引擎注入了上下文属性 `controllers`、`i18n`、`extensionBridge`、`extensionId`、`hostWindow` 和 `wallpaperContext`。除 §4.4 中复用组件要求传入的 `i18n` 外，主题**应当**只通过 `ExtensionApi` 访问它们。

### 4.3 宿主调用主题

【现状】宿主只会主动调用主题的一个动作：完整 Shell 的根 `Item` 如果实现了 `focusSearch()`，按下 `Ctrl+F` 时宿主会通过 C++ 转交调用（`ExtensionView::invokeAction` 只放行这个方法名）。

【约定】新增宿主动作必须有显式接口和测试，不得约定跨引擎调用任意 QML 函数或访问对方的页面树。

### 4.4 跨引擎数据与宿主组件

【约定】跨引擎共享业务状态，只能通过宿主的 C++ 对象和模型。需要传普通值时传值快照；**不得**跨引擎持有 JavaScript 数组、函数、闭包或主题页面实例。主题内部组件用包内相对路径组织。

宿主 `qrc:` 组件的稳定性如下：

| 组件 | 级别 | 用途 |
| --- | --- | --- |
| `qrc:/qml/components/AppearancePanel.qml` | 有限公开 | 完整 Shell 中的外观管理，传入 `controller`、`translator` |
| `qrc:/qml/wallpaper/WallpaperSettings.qml` | 有限公开 | 壁纸设置，传入 `manager`、`themeController`、`translator` |
| `qrc:/qml/components/CompactLyrics.qml` | 有限公开 | 带切歌身份校验和逐字同步的歌词 |
| 其他 `qrc:/qml/...` 资源 | 内部 | 能 `import` 到不代表是公开 API |

【目标】建立有明确属性、信号和兼容约定的公开组件入口，并逐步迁移上述路径；在此之前，不承诺整个宿主资源目录是稳定 SDK。

### 4.5 版本与兼容声明

以下版本号各自独立，**不能互相替代**，也不能证明某个内部控制器方法在所有宿主中都存在：

| 版本 | 约束对象 |
| --- | --- |
| 扩展 `apiVersion` | 扩展清单格式 |
| 主题 `schemaVersion` | 主题贡献格式（变量、变体、`ui`） |
| QML 模块版本（`NekoTune 1.0`） | `ExtensionApi` 等 QML 类型 |
| 原生 SDK ABI | 原生扩展库 |

【约定】主题作者应列出验证过的宿主版本和用到的可选能力；能力缺失时给出提示或回退，不能静默失效。

## 5. 外观、界面与插槽的组合

### 5.1 当前机制

【现状】

- 外观（`selections.theme`）和界面（`selections.themeLayout`）分别保存，壁纸来源通过 `wallpaper.themeWallpaper` 单独指定。`themeLayout` 键不存在时界面跟随外观选择；独立扩展插槽保留自己的选择。
- 每个界面插槽按 **界面选择 → 独立扩展插槽 → 内置实现** 的顺序解析。切走主题不会清除独立插槽偏好；未声明或加载失败的入口会回退到下一层。
- 安全模式下主题固定为内置夜樱，不生成任何 `ui` 插槽。

| 插槽 | 清单字段 | 由谁加载 | 完整 Shell 下是否自动生效 |
| --- | --- | --- | --- |
| `shell` | `ui.shell` | `Main.qml` 顶层；加载成功后不再创建内置 Shell | — |
| `background` | `ui.background` | 内置 Shell 中的 `ThemeBackground` | 否 |
| `bottomPlayer` | `ui.bottomPlayer` | 内置 Shell 的播放栏区域 | 否 |
| `page:<id>` | `ui.pages.<id>` | 内置 Shell 的 `PageHost`；只替换内置页面，不替换扩展页面 | 否 |
| `wallpaper` | `ui.wallpaper` | 壁纸窗口；用户须选择“跟随当前主题”样式 | 与 Shell 无关 |

界面插槽来自界面选择的主题，`variants.*.background` 静态背景来自外观选择的主题；壁纸按独立来源或 §5.3.3 的跟随规则解析。

`ui.pages` 的键必须是校验器允许的内置页面 ID：`home`、`library`、`queue`、`lyrics`、`settings`、`extensions`、`music_sources`、`lyrics_debug`。

### 5.2 完整 Shell 的责任

【现状】`ui.shell` 替换整个窗口内容，根对象必须是 `Item`。宿主**不会**把默认 Shell 的子插槽、工具栏、菜单或扩展页面注入完整 Shell。同一主题即使声明了 `ui.shell` 和其他 `ui` 字段，完整 Shell 也不会自动使用这些字段。

【约定】完整 Shell 必须自行负责：

- 导航与页面组织，包括已注册扩展页面和扩展设置的入口；
- 背景与播放栏；
- 可达的外观管理和恢复说明（可复用 `AppearancePanel.qml`）；
- 断线、加载中和空数据状态的展示。

### 5.3 开发方向：外观、界面、壁纸分开选择

【现状】§5.3.1–§5.3.8 的分开选择、变量合成、按用途授权和外观管理已实现；作者约定及尚未提供的恢复能力在对应段落单独标明。§5.3.9 的完整界面目标仍为【目标】。

#### 5.3.1 分开选择解决的问题

【现状】旧的一次选择同时绑定配色、界面和跟随壁纸。分开保存后可以实现：

- 保留默认布局，只换配色；
- 使用 A 包的布局，搭配 B 包的配色；
- 使用 A 主题，同时使用 B 包的壁纸。

#### 5.3.2 三个独立选项

【现状】

| 选项 | 决定什么 | 来源 | 默认值 |
| --- | --- | --- | --- |
| **外观** | 配色、字体、静态背景（§5.3.4 中归外观的变量） | 主题贡献中的 `tokens`、`variants`、`background` | 内置夜樱 |
| **界面** | `shell`、`pages`、`bottomPlayer`、`background` 等界面入口，以及归界面的变量 | 主题贡献中的 `ui`（`wallpaper` 除外） | 内置界面 |
| **壁纸** | 桌面壁纸布局 | 内置样式、“跟随当前主题”，或指定任意可用贡献中的 `ui.wallpaper` | 现有壁纸设置 |

- 三个选项**各自保存、各自回退**：停用或暂时缺失时保留原选择，恢复可用后自动接回；卸载主题包会清空指向它的配色与界面选择，指定壁纸来源仍保留并提示不可用。
- 一个包可以提供配色、界面和壁纸。外观页用同一张主题卡片提供整套应用及分项按钮；壁纸设置单独列出可用且允许加载的壁纸来源。
- 明暗模式仍是独立的全局选项，作用于外观选择。

#### 5.3.3 解析规则

【现状】前后端共用 `shared/themes/theme_resolution.*` 的变量合成与能力判断。

| 目标 | 解析顺序 |
| --- | --- |
| 变量值 | 基础值 → 外观贡献的公共与变体变量 → 界面贡献对“归界面”变量的覆盖（§5.3.4） |
| 静态背景（`variants.*.background`） | 只来自外观选择 |
| 每个界面插槽 | 界面选择 → 独立扩展插槽选择 → 内置实现 |
| 壁纸 | 指定的来源；“跟随当前主题”时依次取界面选择、外观选择的 `ui.wallpaper` → 内置经典样式 |

- 解析只在宿主中进行一次。主题 QML 读取的 `api.theme` 已经是最终值，**不得**自行再合成。
- 现有“独立扩展插槽”机制保留，位于界面选择之后、内置实现之前；不改变其优先级来模拟分开选择。

#### 5.3.4 自由组合的前提

【约定】任意外观要能和任意界面搭配，双方都必须遵守以下约定；宿主的变量合成规则如下。

**界面不写死外观**：界面贡献**必须**通过 `api.theme` 读取颜色和字体，**不应**写死色值、字体名或背景图片。确实需要固定配色的装饰元素（例如品牌图标），须保证在深色和浅色外观下都清晰可辨。

**【现状】变量按职责归属**：归属写在 `shared/themes/catalog.json` 每个变量的 `group` 字段中，取值为 `appearance`、`layout`、`shared`、`host`。

| 类别 | 归属 | 变量 |
| --- | --- | --- |
| 颜色与氛围 | 外观 | `bg*`、`border*`、`text*`、`accent*`、`status*`、`roseGlow`、`glowOpacity` |
| 字体族 | 外观 | `fontFamily`、`fontFamilyMonospace` |
| 布局尺寸 | 界面 | `sidebarWidth*`、`bottomBarHeight`、`songRowHeight`、`songThumbnailSize`、`controlMinHeight`、`iconButton*`、`playButtonSize`、`artwork*` |
| 字号、行高、间距、圆角、动效时长 | 共享，界面覆盖优先 | `font*`（字体族除外）、`lineHeight*`、`space*`、`radius*`、`duration*` |
| 无障碍偏好 | 宿主（用户设置） | `reducedMotion` |

- 外观贡献中的 `layout` 组变量只在搭配内置界面或该贡献自己的界面时生效；搭配另一贡献的界面时忽略它们，由界面贡献提供 `layout` 组覆盖。`shared` 组变量在独立界面提供对应值时由界面覆盖。
- `reducedMotion` 反映用户的无障碍选择，外观和界面都**不得**覆盖它。
- 归属表随 `catalog.json` 一起维护，新增变量时必须同时标明归属。

**【目标】推荐搭配只是提示**：界面可以推荐一套外观，外观也可以推荐一套界面，但只有用户明确确认后才会应用，不能随选择自动带出。

#### 5.3.5 选择交互

【现状】

- **一键应用**：点击同时提供外观和界面的主题卡片时，默认同时应用两者，保持“点一次换整套”的体验；卡片上同时提供“只用配色”“只用界面”。
- **不含界面的卡片**只改变配色，保留界面和壁纸偏好；壁纸通过独立设置选择。
- 外观页显示当前配色和界面及不可用提示，支持分别重置；动态音乐壁纸设置显示壁纸来源及每屏回退原因。
- 选择外观或界面**不得**自动开启壁纸；壁纸样式只在壁纸设置中选择（§6.3）。

#### 5.3.6 信任

【现状】信任记录以**包**为单位保存，是否请求信任按操作用途判断：

- `type: "theme"` 的主题包无需信任即可启用；通过 `selectAppearance` 只使用配色不请求代码授权。点击不含界面的主题卡片也按配色操作处理，即使包带有 `ui.wallpaper` 也不会因此获得信任或开放壁纸 QML 入口。普通扩展仍须先获得运行代码的信任。
- 含代码的主题包在被信任前，前端不生成任何界面或壁纸 QML 入口；启用包或选用配色不会加载这些代码。
- 选择界面或一键应用含界面代码的主题时请求信任；取消不改变选择。壁纸来源列表只公开可用且允许加载的入口，不替用户授权。

【约定】授权说明应清楚告知将加载的界面代码及其访问能力，不能把启用配色误称为授权代码。

#### 5.3.7 迁移

【现状】**不做一次性迁移**：外观选择沿用 `selections.theme`，界面使用 `selections.themeLayout`；`themeLayout` 键不存在时界面跟随外观选择，空字符串明确表示内置界面。

| 旧状态 | 升级后的解析结果 |
| --- | --- |
| 选中主题 X，X 不提供界面入口 | 外观 = X；界面 = 内置 |
| 选中主题 X，X 提供界面入口 | 外观 = X；界面 = X |
| 独立扩展插槽偏好 | 原样保留，优先级不变 |
| 壁纸 `style: "theme"` | 含义仍是“跟随当前主题”：先取界面选择的壁纸，没有再取外观选择的壁纸，因此只在 `ui` 中提供壁纸的旧主题继续可用 |
| 旧版仅含 `tokens` 的扩展主题 | 只作为外观出现，沿用现有的浅色兼容规则 |

- 旧主题包和清单字段**不需要**任何修改即可在新机制下使用。
- 用户使用新的选择操作后，`theme` 和 `themeLayout` 总是通过批量 `extensions.select` 一起校验并保存，此后不再依赖键缺失时的“跟随”规则。

#### 5.3.8 恢复

【现状】

- 外观页可恢复默认配色、恢复内置界面，或“全部恢复默认”（配色、界面及深色模式）；不清除独立扩展插槽和壁纸偏好。壁纸样式与来源在动态音乐壁纸设置中单独管理。
- 安全模式下外观为夜樱、界面为内置，不加载自定义壁纸，也不自动恢复壁纸；这些回退不修改已保存的选择。
- 恢复窗口（`Ctrl+Shift+E`）固定使用内置样式，复用外观页的配色与界面管理控件。

【目标】恢复窗口直接管理壁纸，以及一次重置配色、界面和壁纸三项，仍待实现。

#### 5.3.9 完整界面相关目标

【目标】

1. **完整界面以 `Shell.qml` 为主入口**，在内部组织页面与组件。现有局部插槽继续兼容，用于小范围替换，不删除旧字段。
2. **Shell 的选择和回退只在宿主入口处理一次**。Shell 内部可以使用局部插槽，但不能再把自己当作 `shell` 插槽加载。
3. **核心功能必须可达**：完整界面模板应保留曲库、歌单、队列、播放、歌词、设置，以及已注册扩展页面和设置的入口，位置和样式可以改变。精简界面必须说明支持范围，并提供回到完整界面的路径。

## 6. 信任、安全与恢复

### 6.1 这不是沙箱

【现状】本文的边界是**产品和开发职责**，不是权限隔离：

- 主题 QML 与宿主共用 GUI 线程，独立 `QQmlEngine` 不隔离死循环、阻塞或恶意脚本。
- `api.call` 可以转发任意 IPC 方法（§4.2），`api.app` 暴露完整的控制器集合。
- 清单和包文件校验只检查格式、路径、资源和大小，**无法**证明代码只做界面工作。

因此，含 QML 或 JavaScript 的主题首次加载其界面或壁纸前需要用户确认信任，信任后获得与普通扩展相同的访问能力；主题包只使用配色不需要代码授权。文档和界面**禁止**用“纯 QML”“只是主题”暗示它没有系统访问能力。纯数据主题（只有变量和图片）不需要代码授权。

### 6.2 宿主保留的控制权

【约定】主题**禁止**：

- 伪造或绕过信任确认，或替用户自动授权扩展；
- 隐藏、吞掉或改写真实错误；
- 遮挡、篡改或模拟恢复入口与管理窗口；
- 修改壁纸、托盘、系统媒体集成等辅助功能的开关偏好。

这些要求只能靠评审保证，不能宣称已通过进程隔离强制执行。

### 6.3 恢复路径

【现状】

| 情形 | 行为 |
| --- | --- |
| 入口编译、创建失败，或根类型不是 `Item` | 显示错误，回退到下一层插槽，其他插槽不受影响 |
| 选中的主题不可用（被禁用、缺失） | 回退到内置夜樱；原选择保留，主题恢复可用后自动接回 |
| `Ctrl+Shift+E` | 打开固定使用内置样式的管理和恢复窗口 |
| `nekotune --safe-mode` | 不加载自定义主题和 QML，禁止启用和重新加载扩展 |
| 运行中的脚本异常、GUI 死循环 | **不保证**自动恢复，需要使用上面两种方式 |

主题音乐壁纸只在用户开启壁纸、并选择“跟随当前主题”样式后显示；选择主题不会自动开启壁纸或任何辅助窗口。

## 7. 默认前端与模板的迁移

【目标】把现有完整前端变成可复用的默认界面主题，让官方界面和导出的主题模板使用同一份界面源码和接口。

【现状】完整界面仍由 `Main.qml` 装配，迁移尚未完成，也没有完整的默认界面开发包。

迁移顺序：

1. **抽出 Shell**：从 `Main.qml` 抽出以 `Item` 为根的默认 `Shell.qml`；主窗口、系统集成、主题选择和恢复入口留在宿主，保留现有功能和页面 ID。
2. **补齐接口**：补上主题实际需要的宿主接口，去掉对隐式上下文、跨引擎 JavaScript 对象和私有页面树的依赖；统一内置资源（`qrc:`）和外部文件的加载方式与引擎配置。【现状】`ExtensionView` 目前只按本地文件路径加载。
3. **导出模板**：把同一份界面源码导出为完整模板，包含页面、组件、对话框和合法资源；业务规则和原生生命周期不复制进主题。开发仓库里的 CI、README 等文件与只含主题文件的安装 ZIP 分开打包。
4. **验证与发布**：在真实宿主中验证导出包后再接入发布。内置主题和外部包遵循同一套公开接口。源码副本不会自动获得官方界面后续的更新，必须记录来源宿主版本。

现有示例与模板的定位：

| 位置 | 定位 | 不承诺 |
| --- | --- | --- |
| `examples/extensions/theme-palette` | 外观主题示例 | 任何界面能力 |
| `examples/extensions/theme-qml` | 局部界面（背景、播放栏）与壁纸示例 | 完整前端 |
| `examples/extensions/custom-ui` | 多种扩展贡献的演示 | 完整前端 |
| `sdk/templates/qml` | 普通页面扩展模板 | 完整主题模板 |

## 8. 评审与验收

新主题、模板和宿主接口变更须逐项检查。标 **必须** 的项不通过则不能合入或发布。

**职责**

- [ ] **必须** 只呈现和调用已有能力；新增业务进入宿主或功能扩展（§1.3）。
- [ ] **必须** 初始化、重载、明暗切换不触发任何业务请求（§2.2）。
- [ ] **必须** 不访问网络提供方、凭据、数据库或用户数据文件。
- [ ] **应当** 只使用 §4 中公开和有限公开的接口；用到内部接口时写明宿主版本并提供回退。
- [ ] **应当** 界面和壁纸通过 `api.theme` 取色，不写死色值、字体名，能与任意外观搭配（§5.3.4）。
- [ ] **必须** 不覆盖 `reducedMotion` 等用户无障碍偏好。

**状态**

- [ ] **必须** 业务状态只有一个权威来源；重建前后播放和队列不变。
- [ ] **必须** 视图销毁不提交草稿；迟到的回调和 `Extension view unloaded` 拒绝不会被应用或误报。
- [ ] **必须** 失败、断线和缺少能力时有明确展示，不能把失败伪装成成功。

**可达性**

- [ ] **必须** 完整 Shell 能到达核心功能、扩展页面和设置入口；精简界面说明能力范围并提供返回路径。
- [ ] **必须** 加载失败回退、独立插槽选择、恢复窗口、安全模式和信任流程保持可用。

**质量**

- [ ] **必须** 内置资源和解压后的外部目录都能加载；完整模板要用实际导出的安装包验收，不能只测源码目录。
- [ ] **应当** 检查深色和浅色、中文和英文、窄窗口、纯键盘操作、减少动态效果；界面变更附实际截图。
